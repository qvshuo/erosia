# erosia

## Runtime and delivery
- Use Docker Compose for builds, deployment and restarts. Python 3.15/pip; local Python checks use `uv run --no-project --python 3.15`. Keep environments, caches, checks and backups outside the repository.
- `erosia/` owns sources, processing, runtime and API; `erosia/web/` uses strict React/TypeScript, Tailwind CSS 4, shared shadcn/ui and Bun. Python serves the static build; production has no frontend runtime. `emby-plugin/erosia/` owns Emby providers.
- Use lowercase erosia for product, packages, assembly, providers, protocol and NFO identifiers. Python, web and plugin versions are 1.4.0. C# changes must rebuild tracked `emby-plugin/erosia.dll`.
- Track `bun.lock`, the plugin DLL, used YuNet model and license. Test suites, frontend tests, plugin verification and fixtures stay outside the repository; production builds must work without them. Exclude dist, caches, real settings, databases, logs, backups and screenshots. Ship only `docker-compose.example.yml`; real Compose/data stay untracked. Verify both the complete program and the full candidate file set, including untracked renamed sources.
- Keep README.md as a concise Chinese quick start, grounded in current behavior. Distinguish container paths from host paths, document fill/refresh/portrait semantics, and describe the Emby plugin as a local-file reader. Compose mount changes require container recreation.
- Defaults: port 9307, settings `/data/settings.json`, metadata `/data/metadata`, FlareSolverr `http://flaresolverr:8191/v1` (blank disables it). Validate bundled runtime resources during build and startup.

## Data and actions
- Product scope: scan → fetch candidates → preview/select → save NFO/images → Emby. No browser import, comparison matrix, probe/statistics dashboard, cleanup UI, recurring watcher or automatic fetch tasks.
- Media is read-only. Exact parent directory names are catalog codes; preserve full prefixes. Invalid/duplicate codes need user correction, appear in the work list's pending group with specific reasons, and cannot be scraped. NFO/images use media filename stems; metadata folders contain only those outputs.
- NFO is authoritative and uncached. Runtime SQLite lives at `/data/runtime/<metadata-path hash>/runtime.sqlite3`, storing indexes, tasks, latest source variants, selections, translation provenance and cooldowns. Keep the service writer lock; no migrations, compatibility aliases, ORM, separate log store or cross-work metadata/translation cache. Settings contain user options only. Emby reads `/erosia-metadata` files directly, never SQLite.
- **Fill missing** is the default batch mode: preserve existing fields/images and customized explicit empty values; retain an existing series. **Refresh** replaces every metadata field, including series, and custom images using the selected source; an absent series clears the old one. Do not replace valid output when fetching, translation or image processing fails.
- Scraping tasks use the configured route; no single-source task or action. Default selection takes the first successful source in user route order; never automatically merge fields or borrow images from another source. Manual field and independent poster/original/sample-group selections are explicit and recorded only in runtime.
- Manual saves use the complete current form as final values; preserve the current NFO series because it is not editable in the form. No NFO/candidate fingerprint conflict or extra save confirmation. Preview drafts stay in memory. Keep per-work write locks and atomic writes; handled file-group failures restore original files. Never claim a rollback that did not occur.
- Stage repair uses saved field originals and pinned failed image inputs, never later candidates or refetched successful metadata. Under the same translation configuration, retry only failed fields; changed configuration translates original text again. Cancellation stops workers, keeps records and successful output, and restores work statuses.

## Metadata and sources
- NFO uses erosia uniqueid, strict Emby fields and canonical field order shared with forms; genres and tags are separate. Actors contain names only; preserve their source order, with no gender parsing or profiles. Studio is the production maker/brand, never a retailer, distributor, actor agency or inferred current exclusivity. Do not fetch, store or display publisher/label.
- Sources: DMM, JavDB (API then web), JavBus, FC2, AVSOX, AirAV, 1Pondo, Caribbeancom, HEYZO, AVbase. Only default routes place JavDB before JavBus; preserve user order. Search takes the first catalog-valid result in provider ranking; retain DMM's verified search order. Official uncensored sources reject unrelated catalogs without requests. Matching is automatic, with no candidate confirmation or source ambiguity status.
- Use Scrapling first and FlareSolverr for challenges. Reuse network connections and each response's parsed DOM; do not retain unused raw payloads. Up to ten works run concurrently; each source finishes one work before accepting another, while all route sources run concurrently for a work.
- Site intervals apply between works, not search/detail/fallback within one work. The batch's first request starts immediately; later requests share pacing budgets and enforce explicit cooldowns. Images share a one-second interval per host.
- Validate translation with benign text before each batch. Configured, valid services translate automatically, with no enable option. One translation request at a time; send only title/description text with the exact prompt, never actor fields, placeholders or script conversion. Protect exact primary and alias names from the actor JSON by translating only the intervening title/description fragments; retain literal names and boundary whitespace. Translation provenance keeps originals and configuration fingerprints, including the matched name set. Tests use benign text only and retain the sample result and duration.
- Use gfriends for portraits in `metadata/actors`, named exactly as NFO actors. Keep one portrait per name. Scraping fetches missing portraits; portrait-update tasks refetch existing portraits without rewriting NFO. Try primary names then safe aliases; retain old portraits on failure. Missing names are normal; ambiguous aliases retain source names without confirmation. Treat actors identically and order their library by work count, portrait availability, then name.
- Actor mappings/rules are JSON only and notice file changes. Key the actor table by JavDB IDs with type/name and optional name_zht/other_name, without a version field. Sort records by (type, ID), one record per line; omit empty optional fields, split comma-separated aliases, remove self-names and deduplicate normalized aliases. Keep raw snapshots outside the repository. Use type 0 for censored and type 1 for uncensored, falling back to a globally unique primary name only when the typed lookup has no match. On scraping, write unambiguous Japanese primary names to NFO; fill missing preserves existing actor fields. Mapping changes affect later scraping only and never rewrite existing NFO. Library searches retain existing NFO names as identities.
- Poster crops use bundled licensed YuNet/OpenCV with a center fallback when no face is found. Face detection is for cover cropping, never actor identification or portrait matching. Save fixed 2:3 crops as lossless PNG without resampling; other images retain original bytes. Artwork opens a draggable 2:3 crop editor without an initial selection; face/center actions create it. Poster/original actions say 应用裁剪, sample actions say 设为封面, based only on the clicked group. Applying changes the in-memory draft; one form save writes fields and images together. No uploads.

## Tasks and projections
- Tasks and items are separate; persist the current item without recounting or rewriting the catalog. Task numbers never reuse. Rebuild metadata/status from NFO on restart; keep derived work lookups indexed in memory.
- Batch serialization and per-work write locks are separate. Only running works are locked against editing. Settings saved during a batch apply to the next batch; output-directory changes wait until the queue is idle.
- Task types are fill missing, refresh and portrait updates only. Run exactly one task at a time, with up to ten works inside it. Queued tasks may overlap works and read predecessor output when they execute. Scans may run during tasks; retain running work identities and never overwrite a newer write with an older scan snapshot.
- Process phases may be transient; final results remain reviewable. Actionable errors persist until explicitly dismissed and are never cleared by background polling. Expose directory warnings, pending settings and normal portrait misses in their relevant views. Keep current-output problems separate from immutable task results.
- A progress panel belongs to one task. Source status, phase, duration and result/error share one projection with actual execution evidence. Existing NFO, routes, queued items and image events are not metadata-fetch evidence. Unstarted sources show names/actions only; historical variants must fall within the task's timestamps. Explain unavailable details without invented counts, pseudo-status or recovery instructions; omit unknown durations and align durations left.
- Repair reports contain only retried stages; cumulative output health and current-file errors/actions stay outside past-task progress. Preserve actual source summaries in completed records. Poll only active tasks and affected works, update only the saved work after saving, and refresh actors on work/task progress rather than source events.
- Task retry/delete actions belong to the task-list operation column. Active details retain cancellation only. Deleting a completed record requires confirmation and never alters metadata; embedded actions must not navigate rows.

## Interface and maintenance
- Works, actors, tasks and settings share segmented navigation, keyboard access and system theme. Tabs provide section names without repeated headings. Product/version belong in the footer. Use shared Select, Checkbox, table/title and metadata-field renderers; whole rows open details independently of embedded controls. Disable unavailable actions and lazy-load optional editors.
- Work lists, task-detail work lists and actor lists support list/grid views, with five grid columns on desktop and fewer on narrow screens. Reuse the work-list renderer between works and tasks, and share selection controls between works and actors.
- Details place editable title before artwork, then other metadata in canonical order; show last progress timestamp beside code/status. Use two expanded columns (images/metadata to progress 2:1), thumbnail grids, grouped cropped/original covers and four-column still grids. All source cards stay inside progress; no NFO-availability label or repeated completed message. Settings stay expanded.
- Lists use shared 14px text; summary counts 16px with a space before Chinese units; settings heading hierarchy 18/16/14px. Chinese UI names use 2–6 characters and descriptions at most 20. Use 扫描作品 and 刮削元数据; preserve protocol identifiers. Dates use 年月日; work progress uses YYYY/MM/DD.
- Branding combines highly abstract wings and a feminine face in black with a white outline on a transparent background. The web favicon SVG is the project icon; Emby embeds a 640×360 PNG via IHasThumbImage. Interface icons follow the system theme.
- Fix confirmed problems where responsibility belongs; do not add layers for tidiness. Remove redundant state, dead parameters and compatibility branches. Shared controls own common styling. Comments explain boundaries, reasons and necessary tradeoffs, not change history. Preserve real metadata and keep backups outside the repository.
